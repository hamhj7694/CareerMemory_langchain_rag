# 에이전트 회의 운영 규칙

## 회의를 여는 경우

요구사항 충돌, API 계약 변경, 디자인과 기술 제약 충돌, Major 이상 결함, 여러 Phase에 영향을 주는 변경이 있을 때만 연다. 단순 진행 공유는 문서로 처리한다.

## 운영 방식

- Router가 안건별 필수 에이전트만 소집한다.
- 한 회의는 하나의 결정 주제를 원칙으로 한다.
- 참석자는 근거, 선택지, 영향만 제시한다.
- Router가 결론·담당·완료 조건을 정리하고 Supervisor가 PRD 정합성을 검토한다.
- 사용자 결정이 필요한 항목만 `사용자 확인`으로 표시한다.

## 회의 기록

`docs/reports/meetings/YYYY-MM-DD-MTG-NNN.md`에 다음 형식으로 남긴다.

```markdown
# MTG-NNN — 안건
- 결론: 한 문장
- 참석: 역할명
- 결정: 최대 3개
- 작업: 작업 ID / 담당 / 완료 조건
- 위험: 없으면 없음
- 사용자 확인: 없으면 없음
```

긴 토론 과정은 사용자 보고에 넣지 않는다. 결정 근거가 필요할 때만 짧게 추가한다.
