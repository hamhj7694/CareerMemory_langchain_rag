# Career Memory V2 디자인 명세

## 1. 제품 경험의 중심

V2의 기본 화면은 관리 대시보드가 아니라 **대화형 커리어 워크스페이스**다. 사용자는 자연어, 파일, 채용공고를 한 입력창에 넣고 AI와 대화한다. AI는 대화에서 확인된 사실을 구조화 초안으로 만들며, 사용자는 우측 패널에서 이를 검토·수정·확정한다.

```text
대화/파일/공고 입력
  → AI 응답·질문·조언
  → 경험 후보와 사실 추출
  → 사용자 검토·수정·확정
  → 경험 관리 화면에 시각화
```

핵심 원칙은 다음과 같다.

- 대화가 진입점이고 경험 관리는 결과를 검증·정돈하는 도구다.
- AI가 추론한 내용과 사용자가 확정한 사실, 원본 근거를 항상 구분한다.
- 구조화는 대화를 방해하지 않고 점진적으로 나타난다.
- 저장은 자동 확정이 아니다. AI 초안은 사용자가 확인하기 전까지 초안 상태다.
- 공고 입력은 별도 세계가 아니라 같은 대화의 컨텍스트 유형이다.

## 2. 정보 구조와 내비게이션

주 내비게이션 순서는 사용 빈도와 제품 중심성에 맞춘다.

1. `챗봇` (`/chat`) — 기본 진입, 대화·파일·공고 입력
2. `경험 관리` (`/memory`) — 구조화된 경험 전체 조회·수정·삭제
3. `채용공고 분석` (`/jobs`) — 저장된 분석 이력과 요구사항 비교

`/`은 `/chat`으로 이동한다. 자기소개서는 독립 최상위 메뉴로 두지 않고 공고 분석 결과 또는 챗봇의 후속 작업에서 진입한다.

## 3. 챗봇 메인 워크스페이스

### 3.1 데스크톱 배치 (1280px 이상)

```text
┌──────────┬─────────────────────────────────┬──────────────────────┐
│ Sidebar  │ Conversation                    │ Structured draft     │
│ 224px    │ minmax(560px, 1fr)              │ 360px                │
│          │                                 │                      │
│ 새 대화  │ thread                          │ 경험 후보/사실/근거  │
│ 대화목록 │                                 │ 수정·확정            │
│          │ sticky composer                 │                      │
└──────────┴─────────────────────────────────┴──────────────────────┘
```

- 앱 사이드바는 224px, 전체 높이이며 주 메뉴와 최근 대화를 함께 제공한다.
- 대화 영역은 최소 560px, 읽기 폭은 메시지 내부 최대 760px로 제한한다.
- 구조화 초안 패널은 360px 고정, 필요 시 420px까지 확장할 수 있다.
- 패널 간 경계는 1px 테두리로 처리하며 중첩 카드와 과도한 그림자를 피한다.
- 대화 헤더와 composer는 sticky, 메시지 스레드만 독립 스크롤한다.

### 3.2 대화 영역

- 빈 화면: 한 문장 가치 제안과 시작 예시 4개를 표시한다.
  - `최근 프로젝트 경험을 정리하고 싶어요`
  - `이 PDF에서 제 성과를 찾아줘`
  - `내 경험 중 데이터 분석 사례가 있어?`
  - `이 채용공고와 내 경험을 비교해줘`
- 사용자 메시지는 우측 정렬 말풍선, AI 응답은 좌측 정렬의 개방형 블록으로 표시한다.
- AI 답변 아래에 `관련 경험`, `원본 근거`, `새로 찾은 사실` 링크를 붙인다.
- 근거 인용을 선택하면 우측 패널의 해당 원문으로 이동하며 잠시 강조한다.
- AI가 확인 질문을 할 때 선택형 답변 칩을 제공하되 자유 입력을 막지 않는다.
- 공고 분석 답변은 요구사항별 `직접 근거 / 부분 근거 / 근거 없음`을 목록으로 보여준다.

### 3.3 통합 composer

composer는 단순 텍스트 입력이 아니라 모든 작업의 시작점이다.

- 여러 줄 텍스트 입력, `Enter` 전송, `Shift+Enter` 줄바꿈
- 첨부 버튼: PDF/TXT 여러 개, 기존 제한(파일당 25MiB·전체 100MiB)을 재사용
- 입력 유형 선택: `일반 대화`, `경험 정리`, `채용공고 분석`
- 붙여넣은 긴 텍스트가 공고로 추정되면 비차단 제안 칩 `채용공고로 분석할까요?`
- 첨부 파일은 전송 전 이름·크기·제거 버튼을 포함한 칩으로 표시
- 전송 중에도 초안은 보존하며 중복 전송을 막는다.
- 음성, URL 자동 수집은 V2 초기 범위 밖으로 둔다.

### 3.4 구조화 draft side panel

패널 헤더는 `정리 중`, `검토 필요`, `저장됨` 상태와 변경 개수를 표시한다.

패널 섹션:

1. **경험 후보** — 제목, 프로젝트, 기간, 역할
2. **사실** — 상황·행동·결과·수치, 사실별 근거 연결
3. **역량** — AI 제안 태그와 사용자 확정 태그 구분
4. **원본 근거** — 대화, 텍스트, 파일 및 페이지
5. **확인 필요** — 모호하거나 근거가 부족한 항목

각 경험 후보는 작은 노드 카드로 표시한다. 카드에는 제목, 완성도, 근거 수, 상태만 노출하고 펼쳤을 때 필드를 편집한다. 하단 고정 액션은 `초안 버리기`, `수정`, `경험으로 확정`이다. 여러 후보가 있으면 개별 확정과 `확인된 항목 모두 저장`을 지원한다.

초안 상태 규칙:

- AI 추출 직후: 보라색 좌측 선과 `AI 초안`
- 사용자가 수정함: 파란색 점과 `수정됨`
- 확정 저장: 초록 체크와 `확정`
- 근거 부족: 호박색 경고와 확인 질문 바로가기
- 충돌 사실: 빨간 경고, 어느 값을 유지할지 선택 전 확정 불가

### 3.5 챗봇 주요 상태

| 상태 | 표현 | 가능한 행동 |
|---|---|---|
| 첫 방문 | 시작 예시 + 빈 composer | 입력·파일 첨부 |
| 응답 생성 | 단계 문구와 작은 진행 표시 | 중지, 입력 초안 작성 |
| 파일 처리 | 파일별 업로드/읽기/완료 상태 | 실패 파일 재시도·제거 |
| 구조화 발견 | 패널 배지와 새 카드 강조 | 검토·수정·확정 |
| 근거 없음 | 답변 안에 한계 고지 | 보충 질문·자료 첨부 |
| 부분 성공 | 성공 결과 유지 + 실패 항목 목록 | 실패 항목만 재시도 |
| 오류 | 메시지 자리의 인라인 오류 | 재시도, 입력 복원 |
| 대화 없음 | 설명 1문장 + 시작 예시 | 새 대화 시작 |

## 4. 경험 관리 시각화

`/memory`는 저장 결과를 한눈에 파악하고 관리하는 화면이다. 기존 트리 전용 구조 대신 **요약 보드 + 필터 가능한 목록/카드**를 기본으로 한다.

### 4.1 상단 요약

- 전체 경험 수, 근거가 연결된 경험 수, 확인이 필요한 경험 수
- 역량 분포는 장식적 차트 대신 클릭 가능한 막대 또는 태그 묶음으로 표현
- `새 경험 정리`는 `/chat?mode=experience`로 이동

### 4.2 검색·필터·보기 전환

- 통합 검색: 제목, 회사, 프로젝트, 사실, 역량
- 필터: 영역, 프로젝트/회사, 기간, 역량, 확정 상태, 근거 유무
- 정렬: 최근 수정, 최신 경험, 오래된 경험, 근거 부족 우선
- 보기: `목록` 기본 / `카드` 선택, 사용자 선택을 로컬에 기억
- 선택 모드: 다중 선택 후 태그 추가 또는 삭제. 초기 구현에서 일괄 삭제만 지원해도 된다.

### 4.3 목록형

행 구성은 `제목·프로젝트`, `기간`, `역할`, `역량`, `근거 수`, `상태`, `더보기`다. 행 전체 선택은 상세 미리보기이며, 수정·삭제는 명시적 버튼/메뉴로 분리한다. 좁은 폭에서는 기간·역량·근거를 두 번째 줄로 접는다.

### 4.4 카드형

카드는 제목, 2줄 요약, 프로젝트·기간, 역량 최대 3개, 근거 수, 확인 필요 상태를 보여준다. 카드 높이를 무리하게 동일하게 맞추지 말고 2줄 요약 이후를 잘라 그리드 리듬을 유지한다. `상세`, `수정`, `삭제`는 hover에만 숨기지 않고 키보드와 터치에서 항상 접근 가능해야 한다.

### 4.5 상세·수정·삭제

- 목록/카드 선택 시 데스크톱은 우측 420px preview drawer, 모바일은 상세 화면으로 이동
- `상세 보기`에서 `/memory/:experienceId`로 이동
- 수정은 필드 단위 편집 또는 전체 편집 모드, 저장 전 dirty 상태 표시
- 삭제는 확인 모달에서 연결 근거·공고 분석에 미치는 영향을 설명
- 삭제 후 5초간 실행 취소 toast를 제공하되 서버가 soft delete를 지원하지 않으면 복구 가능하다고 오인시키지 않는다.
- 원본 근거는 별도 관리 목록에서 텍스트 수정·파일 다운로드·삭제를 유지한다.

## 5. 반응형 레이어

### 데스크톱 (1280px 이상)

- `224px sidebar / flexible chat / 360px draft panel`
- draft panel은 기본 노출, 사용자가 접으면 48px rail로 유지
- 경험 관리는 최대 1440px, 카드 3열(각 최소 280px)

### 태블릿 (768~1279px)

- 앱 내비게이션은 72px 아이콘 rail 또는 overlay drawer
- 챗봇은 대화 단일 본문, draft는 우측 360px overlay drawer
- draft 변경 시 우측 상단 배지와 `정리된 경험 보기` 버튼으로 발견 가능성 보장
- 경험 관리 카드 2열, 목록은 핵심 열만 유지
- drawer backdrop이 대화를 가리지만 대화 상태와 스크롤을 보존

### 모바일 (360~767px)

- 상단 56px 헤더, 하단 주 내비게이션 `챗봇 / 경험 / 공고`
- 대화는 `100dvh`에서 header·composer·safe-area를 제외한 영역만 스크롤
- composer는 기본 1~4줄 자동 확장, 첨부와 입력 유형은 `+` sheet에 배치
- 구조화 draft는 하단 sheet가 아니라 full-screen push 화면으로 연다. 긴 편집과 키보드 충돌을 줄이기 위함이다.
- 메시지 최대 폭 92%, 본문 15px 이상, 터치 영역 최소 44px
- 경험 관리는 1열 카드가 기본이며 목록형 표는 사용하지 않는다.
- 필터는 full-screen sheet, 적용된 필터 수를 상단 칩으로 표시한다.

중단점 사이에서 문장을 글자 중간에 자르지 않도록 제목·설명에 `word-break: keep-all`을 적용한다. 200% 확대에서도 수평 스크롤 없이 핵심 작업이 가능해야 한다.

## 6. 톤앤매너와 시각 언어

톤은 **차분한 대화, 검증 가능한 기억, 사용자 통제**다. 챗봇을 캐릭터화하거나 과도하게 미래적인 AI 화면으로 만들지 않는다.

- 말투: 짧고 구체적이며 판단 근거와 불확실성을 함께 설명
- 표면: 흰색과 옅은 회색 중심, 깊은 그림자 대신 얇은 경계
- Primary blue: 사용자 선택과 주요 CTA
- AI violet: AI 초안과 생성 중 상태에만 제한
- Confirmed green: 사용자가 확정한 사실
- Evidence amber: 원문 인용과 근거 링크
- Danger red: 삭제·충돌·복구 불가 오류
- 큰 그래프나 장식 대신 관계를 보여주는 node card, connector, evidence badge를 사용

## 7. FE-003 토큰 재사용과 추가 토큰

기존 `src/styles/tokens.css`의 색상, 타이포그래피, 4px 공간 체계, radius, shadow, z-index를 그대로 재사용한다. 이는 V2의 근거 구분 의미와 접근성 방향에 부합한다. 새로운 별도 팔레트는 만들지 않는다.

추가가 필요한 레이아웃 토큰:

```css
:root {
  --app-sidebar-width: 224px;
  --chat-content-max: 760px;
  --draft-panel-width: 360px;
  --detail-drawer-width: 420px;
  --composer-max-height: 180px;
  --mobile-header-height: 56px;
  --mobile-nav-height: 64px;
}
```

기존 토큰 중 `--color-ai`, `--color-confirmed`, `--color-evidence`는 배경 전체가 아니라 선·아이콘·배지 중심으로 쓴다. 카드 중첩 시 모든 카드에 radius와 border를 반복하지 않고 섹션 구분선과 여백을 우선한다.

## 9. 접근성과 상호작용 기준

- 대화 새 메시지와 처리 상태는 적절한 live region으로 알리되 토큰 스트리밍마다 읽지 않는다.
- 메시지, 근거, draft 사이 이동을 위한 skip link를 제공한다.
- drawer와 modal은 focus trap 및 닫힌 후 trigger focus 복귀를 보장한다.
- AI/확정/근거 상태는 색만으로 구분하지 않고 아이콘과 텍스트를 병행한다.
- 스트리밍 중지, 재시도, 파일 제거 버튼에 명확한 accessible name을 제공한다.
- `prefers-reduced-motion`에서 메시지 등장·패널 이동 애니메이션을 제거한다.
- 삭제, 대화 초기화, 미저장 draft 이탈은 확인 절차를 둔다.

## 10. V2 디자인 완료 기준

- `/`와 주 내비게이션이 챗봇을 제품의 중심으로 명확히 드러낸다.
- 텍스트·파일·공고가 하나의 composer에서 시작된다.
- 대화 중 생성된 구조화 초안을 확인·수정·확정할 수 있다.
- 경험 관리에서 전체 경험을 검색·필터·목록/카드 조회·수정·삭제할 수 있다.
- AI 초안, 사용자 확정, 원본 근거의 구분이 모든 화면에서 일관된다.
- 1440, 1024, 768, 390px에서 주요 작업이 잘림이나 비정상 줄바꿈 없이 완료된다.
- 빈 상태, 처리 중, 부분 성공, 오류, 근거 없음, 충돌 상태가 구현된다.
- 키보드만으로 대화, draft 검토, 경험 관리, 삭제 확인이 가능하다.
