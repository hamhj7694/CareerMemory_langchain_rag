# Career Memory V2 사용자 흐름 및 화면 상태

- 상위 문서: `docs/v2/V2_PRD.md`
- 원칙: Chat-first, explicit approval, evidence traceability

## 1. 전체 흐름

```text
대화 시작
  → 텍스트/파일 입력
  → 의도 파악 또는 확인 질문
  ├─ 경험 대화 → 구조화 draft → 수정 → 승인 → 경험 관리
  ├─ 경험 질문/조언 → 근거 답변 → 경험 열기/보완
  └─ 공고 입력 → 요구사항 분석 → 내 경험 비교 → 후속 대화/보완
```

## 2. 공통 Chat Workspace 상태

| 상태 | 화면 | 허용 동작 | 보호 규칙 |
|---|---|---|---|
| `new` | 환영 문구, 시작 예시, composer | 입력·첨부 | 없음 |
| `composing` | 입력·첨부 목록 | 전송, 개별/전체 제거 | 새로고침 전 경고 가능 |
| `uploading` | 파일별 progress | 취소 가능 | 중복 전송 차단 |
| `processing` | assistant 진행 표시 | 추가 메시지는 queue 또는 정책 안내 | 같은 요청 재전송 차단 |
| `streaming` | 생성 중 답변 | 중단, 스크롤 | 미완성 답변 표시 |
| `needs-clarification` | 확인 질문 | 응답, 원래 요청 취소 | 원 입력 유지 |
| `draft-ready` | 답변 + 구조화 draft panel | 편집, 승인, 폐기 | 확정 경험과 구분 |
| `partial` | 성공 메시지와 실패 첨부/항목 | 실패 항목 재시도 | 성공 결과 유지 |
| `error` | 간결한 원인·재시도 | 재시도, 입력 수정 | 입력·첨부 유지 |
| `offline` | 연결 끊김 안내 | 로컬 입력 계속, 재연결 | 자동 확정 금지 |

## 3. Flow A — 첫 진입과 대화 시작

### 정상 흐름

1. 사용자가 `/`에 진입하면 `/chat`이 열린다.
2. 최근 대화가 없으면 새 대화 화면과 네 가지 예시를 표시한다.
   - “지난 프로젝트 경험을 정리하고 싶어요.”
   - “내 경험에서 데이터 분석 성과를 찾아줘.”
   - “이직 방향에 대해 조언해줘.”
   - “채용공고와 내 경험을 비교해줘.”
3. 사용자가 텍스트를 쓰거나 PDF/TXT를 첨부한다.
4. 전송 시 대화가 생성되고 URL이 `/chat/:conversationId`로 바뀐다.
5. 사용자 메시지를 즉시 표시하고 assistant 처리 상태를 붙인다.

### 예외

- 빈 텍스트이며 첨부도 없음: 전송 비활성화
- 지원하지 않는 형식/크기 초과: 해당 파일만 거부하고 나머지는 유지
- 전체 용량 초과: 제거가 필요한 용량을 안내
- 업로드 일부 실패: 성공 파일은 유지하고 실패 파일만 재시도
- 대화 생성 실패: composer 내용을 보존

## 4. Flow B — 대화로 경험 구조화

### 정상 흐름

1. 사용자가 자유로운 경험 설명 또는 자료를 보낸다.
2. assistant는 이해한 내용과 빠진 핵심 정보를 대화로 확인한다.
3. 충분한 정보가 모이면 구조화 draft를 제안한다.
4. draft panel에 영역, 프로젝트, 경험 제목, 요약, 상황, 행동, 결과, 역할, 사실, 역량, 부족한 정보, 원본 근거를 표시한다.
5. 사용자는 필드를 직접 수정하거나 대화로 수정 요청한다.
6. AI에 의해 갱신된 값은 변경 표시를 제공한다.
7. 사용자가 `[경험으로 저장]`을 누른다.
8. 검증 성공 후 승인 요청을 보내고 저장된 경험 링크를 답변에 표시한다.

### 저장 전 규칙

- draft 생성만으로 경험 library에 확정 데이터를 만들지 않는다.
- 필수값 누락, 근거 없는 정량 성과, 충돌하는 기간은 경고한다.
- 경고가 있어도 저장 가능한 항목과 차단 항목을 구분한다.
- draft 폐기 시 확정 경험은 변경하지 않는다.

### 예외

- 경험을 찾지 못함: 더 구체적인 상황·행동·결과 질문 제시
- 여러 경험이 섞임: 경험 후보를 분리해 각각 승인하도록 제안
- 기존 경험과 중복 후보: 새로 저장/기존 경험에 병합/취소 선택
- version conflict: 최신 draft와 내 편집 차이를 보여주고 재적용
- 승인 실패: 편집 내용을 유지하고 재시도

## 5. Flow C — 저장 경험 질문과 조언

### 정상 흐름

1. 사용자가 저장된 경험에 관한 질문이나 진로 조언을 요청한다.
2. assistant 답변은 관련 경험 카드와 인라인 근거를 포함한다.
3. 근거를 선택하면 출처 drawer에서 대화 텍스트 또는 파일 정보를 본다.
4. 경험 카드를 선택하면 상세 panel 또는 `/memory/:experienceId`를 연다.
5. 부족한 정보가 발견되면 `[이 경험 보완하기]`로 현재 채팅에 후속 질문을 시작한다.

### 응답 규칙

- 저장된 근거, 일반 조언, 추론을 구분한다.
- 관련 경험이 없으면 없다고 알리고 새 경험 입력 또는 질문 구체화를 제안한다.
- 근거가 불충분하면 확정적으로 표현하지 않는다.

### 예외

- 답변 생성 실패: 사용자 질문을 보존하고 재시도
- 일부 근거 접근 불가: 답변은 유지하되 unavailable 표시
- 삭제된 경험 링크: 삭제됨 안내와 library 이동 제공

## 6. Flow D — 채용공고 입력과 경험 비교

### 정상 흐름

1. 사용자가 채용공고 원문을 붙여 넣거나 파일로 첨부한다.
2. 의도가 명확하면 assistant가 공고 분석 시작을 알린다. 불명확하면 “채용공고로 분석할까요?”라고 확인한다.
3. 회사·직무·요구사항 초안을 대화 안에서 보여준다.
4. 사용자 확인 후 저장 경험과 비교한다.
5. 요구사항별 `직접 근거/부분 근거/간접 근거/근거 없음/확인 필요`를 표시한다.
6. 각 결과에서 관련 경험과 원본 근거를 열 수 있다.
7. 후속 액션은 경험 보완, 조언 계속하기, 공고 상세 열기다.

### 예외

- 공고로 판단하기 어려움: 직무·회사 또는 분석 의도 확인
- 요구사항 추출 실패: 원문 보완 또는 다시 분석
- 저장 경험 없음: 공고는 유지하고 첫 경험 만들기 유도
- 일부 매칭 실패: 성공 요구사항 유지, 실패 항목만 재시도

## 7. Flow E — 경험 전체 관리

### 정상 흐름

1. 사용자가 `/memory`로 이동한다.
2. 기본은 최근 수정 순 전체 경험 카드/목록이다.
3. 검색하거나 영역·프로젝트·역량·근거 상태로 필터한다.
4. 구조 보기에서 `영역 → 프로젝트 → 경험` 그룹과 근거 수를 확인한다.
5. 항목 선택 시 요약 detail panel을 열고, 전체 상세로 이동할 수 있다.
6. 경험을 직접 수정·저장하거나 삭제한다.
7. `[챗봇에서 열기]`를 누르면 경험 컨텍스트가 붙은 새/기존 대화로 이동한다.

### 삭제 규칙

- 삭제 대상 제목과 영향 범위를 확인한다.
- 경험 삭제와 원본 파일 삭제는 별개다.
- 삭제된 경험을 참조하던 답변·공고에는 unavailable 상태를 표시한다.
- 영구 삭제/복원 정책이 API에서 확정되기 전에는 soft delete를 전제로 한다.

### 예외

- 경험 없음: 첫 대화 시작 CTA
- 검색 결과 없음: 필터 초기화
- 저장 충돌: 최신본 비교
- 일부 목록 로드 실패: 성공 카드 유지, 실패 영역 재시도

## 8. Flow F — 원본 근거 관리

1. 경험 상세 또는 답변 근거를 통해 source drawer를 연다.
2. 텍스트 근거는 읽기·수정·저장할 수 있다.
3. 파일 근거는 메타데이터와 인용 위치를 보고 다운로드할 수 있다.
4. 둘 다 삭제할 수 있으며 연결 경험에 미치는 영향을 확인한다.
5. 원본 삭제 후 경험 사실은 자동 삭제하지 않고 `근거 없음/검토 필요`로 갱신한다.

예외: 다운로드 만료·원본 없음·권한 오류를 구분하고, 상세 화면 자체는 유지한다.

## 9. Flow G — 대화 복원과 이탈

- `/chat/:id` 새로고침 시 메시지, 첨부 상태, 활성 draft를 복원한다.
- 승인 전 로컬 편집이 있으면 라우트 이동·탭 종료 전에 경고한다.
- processing 중 이탈해도 서버 작업 ID가 있으면 재진입 시 상태를 조회한다.
- 존재하지 않거나 보관된 대화는 새 대화/목록 이동을 제공한다.
- 대화 보관은 경험·근거를 삭제하지 않는다.

## 10. 반응형 행동

### 넓은 화면

- 좌측 대화 목록, 중앙 메시지, 우측 context/draft panel의 3영역
- 우측 panel이 닫혀 있으면 중앙 영역 확장

### 중간 화면

- 대화 목록 collapse
- context/draft는 overlay drawer
- 제목과 설명은 공간이 충분할 때 가로, 좁으면 세로 배치

### 모바일

- 메시지와 composer 우선
- 대화 목록과 draft는 full-screen sheet
- 전송·승인 버튼이 키보드에 가려지지 않음
- 한글 단어 중간 줄바꿈 방지

## 11. 화면별 완료 조건

### Chat Workspace

- 새/기존 대화, 다중 첨부, 메시지 상태, 근거, draft 승인 흐름을 한 화면에서 수행
- 오류 후 입력과 편집 유지
- 키보드만으로 전송·첨부 제거·draft 검토 가능

### Experience Library

- 전체 경험을 검색·필터·정렬하고 상세·수정·삭제로 이동
- 영역·프로젝트·경험 관계를 시각적으로 파악
- 보완 필요와 근거 없음 상태 식별

### Job Analysis

- 채팅에서 시작한 공고를 목록/상세에서 복원
- 요구사항별 경험과 근거 또는 근거 없음 표시

## 12. V1 화면 전환 매핑

| V1 | V2 |
|---|---|
| `/memory` 저장된 경험 탭 | `/memory` Experience Library |
| `/memory` 새 경험 입력 탭 | `/chat` composer |
| `/memory` 경험 질문 탭 | `/chat` 기본 대화 |
| 구조화 결과 전체 화면 | `/chat` draft panel |
| `/memory/:id` | 유지하되 chat 연결 강화 |
| `/jobs` 입력 폼 | `/chat` 또는 `/jobs` 보조 진입 |
| `/jobs/:id` | 유지, chat 후속 액션 추가 |
| `/documents/:id` | V2 핵심 내비게이션에서 제외 |

V1 사용자가 기존 URL로 진입해도 데이터 손실 없이 대응 V2 화면으로 안내하거나 redirect한다.
