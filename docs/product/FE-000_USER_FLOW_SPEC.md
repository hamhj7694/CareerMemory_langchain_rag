# FE-000 사용자 흐름 및 화면 상태 명세

- 상태: Approved
- 기준: `PRD.md` V1
- 범위: 프론트엔드 사용자 흐름과 관찰 가능한 UI 상태
- 제외: LLM·RAG·DB·파일 본문 추출 등 AI 엔진 내부 처리

## 1. 목적과 원칙

사용자는 정리되지 않은 경험을 입력하고, AI의 구조화 결과를 직접 확인·수정한 뒤 저장한다. 저장된 경험을 검색·질문하고 채용공고와 대조해 근거 기반 자기소개서를 작성한다.

흐름 전체에 다음 원칙을 적용한다.

1. AI 결과는 저장 전에 반드시 사용자가 확인한다.
2. AI 제안, 사용자 확정 정보, 원본 근거를 구분한다.
3. 장시간 요청에는 진행 상태를 표시하고 중복 제출을 막는다.
4. 실패해도 사용자가 입력·편집한 내용을 보존하고 재시도할 수 있게 한다.
5. API가 준비되지 않은 동안에도 동일한 화면 모델의 Mock으로 흐름을 검증한다.
6. 사용자에게 서버·LLM 내부 단계 대신 현재 할 일과 결과를 설명한다.

### 전제

- V1은 인증이 없는 단일 사용자 환경이다.
- React가 최종 사용자 UI이며 Gradio는 AI 엔진 내부 테스트용이다.
- 프론트엔드는 파일 내용을 직접 추출하거나 AI 판단을 수행하지 않는다.

### V1 제외

외부 공고 API, 자동 공고 추천, 여러 공고 동시 비교, 회원·다중 사용자, 면접·지원 결과 분석, 모바일 완전 최적화, 음성 입력, Notion·Drive 연동, 자유 그래프·고급 Canvas, 합격 가능성 계산은 제외한다. 드래그앤드롭, 경험 병합·자동 분할, 복잡한 관계 그래프도 제외한다.

## 2. 정보 구조와 라우트

| 라우트 | 화면 목적 | 주요 진입 | 주요 이탈 |
|---|---|---|---|
| `/memory` | 경험 입력, 구조화 검토, 트리 조회, 경험 질문 | 기본 진입, 사이드바 | 경험 상세, 채용공고 분석 |
| `/memory/:experienceId` | 경험 상세·수정·원본·질문 | 경험 트리/검색 결과 | `/memory`, 관련 공고 |
| `/jobs` | 채용공고 입력 및 분석 시작 | 사이드바 | `/jobs/:jobId` |
| `/jobs/:jobId` | 요구사항 확인, 경험 대조·선택, 자소서 생성 | 공고 분석 완료 | 문서 편집, 경험 상세 |
| `/documents/:documentId` | 생성 자기소개서 확인·직접 편집·AI 수정 | 생성 완료 | 원래 공고 상세 |

### `/memory` 내부 모드

복합 화면이므로 URL 변경 없이 다음 모드를 명시적으로 관리한다.

- `browse`: 기본값. 저장 경험 트리와 시작 안내 표시
- `input`: 텍스트/파일 입력
- `review`: AI 구조화 결과 확인·수정·연결·저장
- `chat`: 경험 질문과 근거 결과

새로고침 시 서버에 저장되지 않은 `input/review` 임시 데이터 복구는 V1 필수가 아니다. 이탈 시 미저장 변경 경고는 필수다.

## 3. 공통 화면 상태

| 상태 | 표시 | 허용 동작 | 금지/보호 동작 |
|---|---|---|---|
| `initial` | 목적·입력 안내 | 입력 시작, 기존 경험 조회 | 없음 |
| `loading` | 대상 영역 skeleton/spinner | 취소 가능 시 취소 | 중복 요청 |
| `processing` | 분석 중 문구와 진행 표시 | 안전한 탐색만 허용 | 동일 분석 재제출 |
| `success` | 결과와 다음 핵심 액션 | 검토·편집·저장 | 자동 확정 |
| `empty` | 데이터 없음과 생성 CTA | 입력 시작 | 빈 영역만 표시 |
| `error-retryable` | 원인 요약·재시도 | 재시도, 입력 유지 | 입력 초기화 |
| `error-validation` | 필드 인접 오류 | 수정 후 재제출 | 유효하지 않은 제출 |
| `saving` | 저장 중, 버튼 disabled | 화면 내 대기 | 중복 저장·이탈 |
| `saved` | 저장 성공, 트리 갱신 | 상세 보기, 새 입력 | 같은 payload 재저장 |
| `dirty` | 미저장 변경 표시 | 저장, 변경 취소 | 경고 없는 이탈 |

공통 오류는 기술 메시지를 그대로 노출하지 않는다. 필드 오류는 해당 필드 근처, 페이지 오류는 해당 작업 영역, 전역 연결 오류만 공통 알림에 표시한다. 진행률을 알 수 없는 AI 작업에는 가짜 퍼센트를 표시하지 않는다.

## 4. Journey A — 경험 입력·구조화·저장

PRD: FE-M01~M06

### A1. 시작과 입력

1. 사용자가 `/memory`에 진입한다.
2. 저장 경험이 있으면 `browse`, 없으면 empty 상태와 `[경험 입력하기]` CTA를 표시한다.
3. 사용자가 `input` 모드에서 텍스트 또는 파일 방식을 선택한다.
4. 텍스트는 공백만 입력할 수 없고, 파일은 PDF/TXT·크기·중복 여부를 검증한다.
5. 유효한 입력에서 `[경험 정리하기]`를 실행한다.

상태 전이: `initial/empty → input → validation-error | processing → review | retryable-error`

### A2. 구조화 결과 검토

1. 성공 응답을 영역 → 프로젝트 → 개별 경험 계층으로 표시한다.
2. 사용자는 제목, 요약, 상황, 행동, 결과, 역할, 사실, 역량, 누락 정보를 수정한다.
3. 배열 항목과 역량 태그, 개별 경험을 추가·삭제할 수 있다.
4. 기존 프로젝트 후보가 있으면 `기존 프로젝트`, `새 프로젝트`, `보류` 중 선택한다.
5. AI가 제안한 내용은 확정 정보처럼 보이지 않아야 한다.

상태 전이: `review-clean → review-dirty → validation-error | saving`

### A3. 확정 저장

1. 필수 필드와 연결 선택을 검증한다.
2. 저장 중 편집·중복 제출·경고 없는 이탈을 막는다.
3. 성공하면 경험 트리를 갱신하고 새 경험을 강조한다.
4. 실패하면 편집 내용을 유지하고 오류·재시도를 제공한다.

완료 결과: 사용자가 저장 위치와 새 경험을 명확히 확인한다.

### A 예외 흐름

- 공백 텍스트: 제출하지 않고 입력 필드 오류
- 분석 중 재클릭: 요청 추가 생성 없이 버튼 비활성
- 허용되지 않은 파일/초과 크기: 업로드 전에 오류
- 네트워크/서버 실패: 원문·파일 선택·편집 내용 유지
- 결과가 비어 있음: “구조화할 경험을 찾지 못함”과 입력 보완 안내
- 기존 프로젝트 후보 없음: 새 프로젝트 또는 보류만 표시
- 경험 삭제: 저장 전 확인, 마지막 경험 삭제 시 저장 가능 여부를 명확히 안내
- `보류`: 서버 보존·재진입 계약이 없으므로 V1에서는 저장 위치 결정 연기로만 표현하고 장기 보존을 약속하지 않음
- dirty 상태 이탈: 확인 모달

## 5. Journey B — 경험 조회·상세·원본

PRD: FE-M07~M09

1. `/memory`의 `browse` 모드에서 영역 → 프로젝트 → 경험 트리를 조회한다.
2. 노드를 펼치고 접으며 선택 경험을 강조한다.
3. 경험을 선택하면 `/memory/:experienceId`로 이동한다.
4. 상세에서 요약·상황·행동·결과·역할·역량·원본 근거를 확인한다.
5. 수정 후 저장하거나 `[원본 보기]`로 modal/panel을 연다.
6. 원본에는 텍스트, 파일명, 페이지, 입력 시각, 연결 사실을 표시한다.

예외 상태:

- 트리 없음: 첫 경험 입력 CTA
- 일부 노드 로딩 실패: 전체 화면을 막지 않고 해당 영역 재시도
- 존재하지 않는 ID: 찾을 수 없음 + `/memory` 복귀
- 원본 없음: 원본이 등록되지 않았음을 명시
- 수정 실패: 변경 유지 + 재시도
- `숨기기`: PRD에 API 의미가 없어 FE-001에서 PATCH 계약이 확정되기 전 구현 보류

## 6. Journey C — 경험 RAG 질문

PRD: FE-M10~M11

1. 사용자가 `/memory`의 `chat` 또는 경험 상세에서 질문을 입력한다.
2. 공백 질문을 차단하고 요청 중 동일 제출을 막는다.
3. 응답에는 답변, 관련 경험 카드, 프로젝트, 근거 문장, 부족한 정보를 표시한다.
4. 관련 경험 카드를 선택하면 상세를 열되 대화 맥락을 유지한다.
5. 원본 보기와 자기소개서 사용으로 이어질 수 있다.

예외 상태:

- 관련 경험 없음: 사실을 만들지 않고 “찾지 못함”과 질문 보완 안내
- 답변은 있으나 근거 없음: 근거 부족 경고
- 요청 실패: 질문을 입력창 또는 대화 기록에 유지하고 재시도
- 과거 대화 유지 범위는 V1 계약 확정 전 현재 세션으로 한정

## 7. Journey D — 공고 분석·경험 대조

PRD: FE-J01~J04

### D1. 공고 분석

1. `/jobs`에서 회사명·직무명·공고 원문을 입력한다. 자기소개서 문항은 경험 비교가 끝난 뒤 생성 단계에서 입력한다.
2. 공고 원문은 필수이며 공백 제출을 막는다.
3. 분석 중 입력을 보존하고 중복 요청을 막는다.
4. 성공하면 `/jobs/:jobId`에서 요구사항을 유형별 카드로 표시한다.

상태 전이: `job-input → analyzing → analysis-ready | retryable-error`

### D2. 경험 대조

1. `[내 경험과 대조하기]`를 실행한다.
2. 요구사항별 판정, 관련 경험, 근거, 부족 정보, 추천 이유를 표시한다.
3. 판정은 `direct`, `partial`, `indirect`, `no_evidence`, `needs_confirmation`을 사용자 언어로 보여준다.
4. 사용자가 자기소개서에 사용할 경험 1~2개를 선택한다.

상태 전이: `analysis-ready → matching → match-ready → experience-selected`

예외 상태:

- 요구사항 없음: 원문 보완 또는 재분석
- 저장 경험 없음: 경험 입력 CTA, 현재 공고 입력 보존
- 매칭 없음: 적합성을 과장하지 않고 근거 없음 표시
- 일부 요구사항 실패: 성공 항목 유지, 실패 항목별 재시도

## 8. Journey E — 자기소개서 생성·편집

PRD: FE-C01~C04

1. 공고 상세에서 경험 1~2개를 선택한다.
2. 문항, 글자 수, 문체를 입력·선택한다.
3. 필수 조건과 경험 선택 개수를 검증한다.
4. 생성 중 조건 변경과 중복 요청을 막는다.
5. 성공하면 `/documents/:documentId`에서 문서, 글자 수, 사용 경험·근거, 부족 정보 경고를 표시한다.
6. 사용자는 직접 편집하거나 `shorten`, `expand`, `natural`, `rewrite` 수정을 요청한다.

상태 전이: `options → generating → document-ready → editing-dirty | revising → document-ready`

예외 상태:

- 선택 경험 0개 또는 3개 이상: 생성 차단
- 근거 부족: 생성 결과와 함께 눈에 띄는 경고
- 생성/수정 실패: 기존 문서와 사용자 편집 내용 보존
- AI 수정 성공: 직접 편집을 즉시 덮어쓰지 않고 최소 1단계 되돌리기 또는 적용 확인 제공
- 글자 수 초과: 현재/제한 글자 수 표시, 저장·사용 정책은 API 계약에서 확정
- 문서 ID 없음: 공고 상세로 복귀 안내

## 9. 공통 내비게이션·이탈 규칙

- Sidebar는 `경험 메모리`, `채용공고 분석`을 항상 제공한다.
- Header는 현재 페이지 제목, 처리 상태, 필요한 이전 화면 동작을 표시한다.
- 저장·분석·생성 중에는 해당 작업 영역의 이동을 보호한다.
- dirty 상태에서 라우트 이동·브라우저 종료 시 경고한다.
- 상세에서 목록으로 돌아가면 가능하면 이전 펼침·선택 상태를 복원한다.
- 오류 후 재시도는 사용자가 입력한 값을 초기화하지 않는다.

## 12. Acceptance Criteria

- AC-01: 모든 V1 기능 ID가 하나 이상의 정상 사용자 흐름에 연결된다.
- AC-02: `/memory`, `/memory/:id`, `/jobs`, `/jobs/:id`, `/documents/:id`의 목적과 전환이 정의된다.
- AC-03: 모든 비동기 작업에 initial/loading/success/error/empty 또는 해당 없음이 정의된다.
- AC-04: 분석·저장·생성 요청의 중복 제출을 막는다.
- AC-05: 실패와 재시도 과정에서 사용자 입력·편집 내용을 보존한다.
- AC-06: 미저장 변경 이탈 보호가 정의된다.
- AC-07: AI 제안·사용자 확정·원본 근거의 구분 원칙이 있다.
- AC-08: API 미확정 사항이 화면 가정으로 숨지 않고 계약 문서에 연결된다.
- AC-09: PRD 제외 기능이나 AI 엔진 내부 구현이 포함되지 않는다.
- AC-10: Planner, Designer, QA, Supervisor가 후속 작업에 사용할 수 있다.
