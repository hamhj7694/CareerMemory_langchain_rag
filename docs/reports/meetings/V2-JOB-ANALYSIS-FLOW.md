# 채용공고 분석 흐름 개선 회의

- 일자: 2026-07-22
- 참여: Planner, Designer, Supervisor/QA, Frontend
- 결론: 사용자 제안 흐름 채택

## 결정한 사용자 흐름

1. `/jobs`에서 기존 분석 기록을 검색·정렬하고 상세로 재진입한다.
2. 새 공고를 분석하면 요구사항 추출 후 경험 대조를 자동으로 1회 시작한다.
3. `/jobs/:id`는 저장된 요구사항과 최신 대조 결과를 즉시 표시한다.
4. 요구사항별 관련 경험·판정·이유·원본 근거·부족 정보를 함께 보여준다.
5. 사용자가 경험 1~2개를 선택한다.
6. `선택 경험으로 작성하기`를 누른다.
7. 작성 설정에서 문항·글자 수·문체를 확인한 후 초안을 생성한다.
8. 문서 편집 화면에서도 공고·대조 결과·선택 경험 맥락을 유지한다.

`내 경험과 대조하기` 1차 버튼은 제거한다. 이 버튼은 최초 실행이 아니라 실패 재시도 또는 `최신 경험으로 다시 대조`에만 사용한다.

## 화면 구성

### 분석 기록

- 회사명, 직무명, 분석일
- 필수/우대 요구사항 수
- 대조 상태: 진행 중·완료·일부 실패·업데이트 필요
- 선택 경험과 작성 문서 존재 여부
- 행 클릭 상세, `···`에서 보관/삭제

### 분석 상세

- 상단 요약: 필수·우대·직접 근거·보완 필요·근거 없음 수
- 요구사항 카드: 중요도, 판정, 관련 경험, 매칭 이유, 근거 인용, 부족 정보
- 선택 경험 패널: 전역 선택 상태, 최대 선택 수와 커버하는 요구사항 표시
- 주 CTA: `선택 경험으로 작성하기`
- 작성 옵션은 CTA 이후 모달/별도 단계에서 표시

## 자동 대조 정책

- 신규 분석 완료 시 1회 자동 실행
- 기존 상세 진입은 저장 결과 재사용, 자동 재실행 금지
- `공고 hash + 경험 corpus version + matcher version`이 같으면 캐시 사용
- 경험 변경 시 기존 결과를 유지하며 `업데이트 필요` 표시
- 부분 실패는 성공 결과를 유지하고 실패한 요구사항만 재시도

## 필요한 API

- `GET /jobs?cursor&query&status`: 분석 기록
- `GET /jobs/{id}`: 공고·요구사항·최신 대조 요약
- `POST /jobs/{id}/match`: 비동기 대조 시작, 중복 요청 방지
- `GET /jobs/{id}/match-runs/{runId}` 또는 SSE: 진행·부분 실패·완료
- 작성 생성 시 `job_id`, `match_run_id`, `experience_ids`, 문항 설정 검증

## 예외 처리

- 관련 경험 없음: 직접 경험 선택, 경험 추가, AI와 경험 정리
- 요구사항 없음: 공고 원문 보완 또는 새 분석
- 삭제된 경험: 과거 스냅샷은 표시하되 작성에는 사용 불가
- 삭제된 근거: 사용 불가 표시 후 생성 근거에서 제외
- 모바일: 단일 열 요구사항 목록 + 하단 고정 선택/작성 바

## 구현 우선순위

1. 분석 기록 및 저장된 대조 결과 Mock/API
2. 신규 분석 후 자동 대조와 재진입 복원
3. 요구사항별 경험·근거 표시와 전역 선택
4. 작성 설정 단계 분리 및 문서 화면 연결
5. 부분 재시도·업데이트 필요·삭제 경험 처리
