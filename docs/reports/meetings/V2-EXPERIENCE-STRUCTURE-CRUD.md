# 경험 구조 CRUD 개선 회의

- 일자: 2026-07-22
- 참여: Planner, Designer, Supervisor/QA, Frontend
- 결론: 개선 필요. 현재 빈 프로젝트 로컬 삭제는 정식 기능으로 출시 보류

## 결정

1. UI 계층 명칭은 `경험 분류 → 프로젝트·활동 → 경험`으로 변경한다.
   - 기존 내부 필드 `domain`, `project`는 API 이관 전까지 유지한다.
2. 관리 화면에서 세 계층을 모두 직접 추가·수정·이동·삭제할 수 있게 한다.
3. 상단에는 `[+ 직접 추가] [AI와 경험 정리] [선택]`을 둔다.
4. 경험의 복수 선택·이동·일괄 삭제를 제공한다.
5. 삭제 진입점은 항상 제공하되 `···` 메뉴에 넣어 좁은 화면의 제목 공간을 보호한다.
6. 빈 분류/프로젝트·활동은 자동 삭제하지 않는다.

## 삭제 원칙

- 빈 상위 항목: 이름을 표시하고 확인 후 삭제
- 내용이 있는 상위 항목: `다른 곳으로 이동 후 삭제`를 기본으로 제공
- `하위 경험과 함께 삭제`는 별도 위험 작업으로 분리하고 영향 수를 표시
- 경험 단건·일괄 삭제: 영향 조회 → 명시 확인 → soft delete → 실행 취소/휴지통
- 원본 근거는 별도 선택이 없으면 유지
- 공고·문서·대화 참조는 ID를 보존하고 `삭제됨/사용 불가`로 표시

## 직접 추가

- 경험 분류: 이름
- 프로젝트·활동: 이름, 조직, 기간(선택)
- 경험: 제목 필수, 역할·요약·성과·역량·근거 선택
- 직접 추가한 경험은 바로 저장하되 근거가 없으면 `근거 없음` 표시
- 저장 후 `AI로 보완하기`로 해당 경험을 챗 컨텍스트에 전달

## 구현 순서

1. 분류·프로젝트·활동 독립 ID/version/soft-delete API 계약
2. 각 계층 `+ 추가`와 이름 변경
3. `···` 관리 메뉴와 영향 확인 삭제
4. 직접 경험 추가 폼과 `AI로 보완하기`
5. 경험 선택 모드, 일괄 이동·삭제
6. 실행 취소·휴지통·복원 및 참조 무결성 QA

## 출시 조건

- 새로고침·다중 세션에서도 구조 CRUD 유지
- 삭제 영향 API와 공고·문서·근거 참조 검증
- 409 충돌, 중복 요청, 일괄 실패 정책 검증
- 키보드·모바일에서 추가·이동·삭제 가능
