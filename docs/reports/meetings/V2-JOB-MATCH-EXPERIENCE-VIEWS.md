# 공고 매칭 경험 보기 개선 회의

- 일자: 2026-07-23
- 참여 관점: 기획, 프론트엔드·디자인, QA
- 결론: AI 추천·전체·선택 보기는 동일한 구조형 목록에 서로 다른 필터를 적용한다.

## 확정 구조

상단에 다음 3개 탭을 둔다.

1. `AI 추천 N`
2. `전체 경험 N`
3. `선택한 경험 N`

모든 탭은 `경험 분류 → 프로젝트·활동 → 경험 카드` 구조를 사용한다.

- AI 추천: 전체 경험 중 AI 추천 ID만 표시
- 전체 경험: 모든 경험 표시
- 선택한 경험: 사용자가 체크한 경험만 표시
- 추천 경험은 모든 탭에서 `AI 추천` 배지를 유지

## 선택 상태

- 경험 ID 기반의 단일 선택 상태를 세 탭과 자기소개서 작성 단계가 공유한다.
- 어느 탭에서 체크·해제해도 다른 탭에 즉시 반영한다.
- 최대 2개 선택을 유지한다.
- 2개 도달 후 추가 선택 시 `최대 2개까지 선택할 수 있습니다.`를 안내한다.
- 탭 아래에 선택 경험 제목과 제거 버튼을 제공하는 요약 영역을 둔다.

## 빈 상태

- 추천 없음: 전체 경험에서 직접 선택하도록 안내
- 전체 경험 없음: 경험 등록으로 이동
- 선택 없음: AI 추천 또는 전체 경험 보기로 이동

## 핵심 QA

- 추천에서 선택한 경험이 전체·선택 탭에도 체크되어야 한다.
- 전체에서 해제하면 추천·선택 탭에도 즉시 반영되어야 한다.
- 보기 전환과 분류 접기·펴기 후에도 선택이 유지되어야 한다.
- AI 추천이 바뀌어도 사용자가 직접 선택한 경험은 자동 해제하지 않는다.
- 자기소개서 생성 요청의 경험 ID가 화면의 선택 항목과 일치해야 한다.

## 구현 방향

`allExperiences + recommendedIds + selectedIds + activeView`를 단일 상태 모델로 사용하고, 하나의 구조형 경험 목록 컴포넌트에 필터 결과만 전달한다.
